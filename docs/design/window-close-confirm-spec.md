## 1 结构（三段式）

| 段 | 高度 | 内距 | 内容 |
|---|---|---|---|
| ① 头部 | 见 §2 | — | 标题「关闭主窗口」+ 说明 + × (26×26，hover 红底白字) |
| ② 关闭行为 | **140px（写死）** | `14 18` | 「记住我的选择」勾选行；两张卡片 **82px**，间距 10px |
| ③ 底部 | **62px（写死）** | `14 18` | 左「Esc  取消」11px；右「取消」GhostButton |

- 卡片整体宽 **440px**，圆角 10px，1px `border-strong`，阴影 blur 24px。
- 段间 1px `border-subtle` 分隔线（两条）。
- **段高写死整数**的理由（代码注释 `#close-dialog-lines 2026-09-18`）：弹框垂直居中 +
  1.25 UI 缩放会让 1px 分隔线落在不同亚像素相位，出现"一条清晰一条发糊"。段高恒定后
  两条线的 y 只差整数 → 同相位 → 粗细一致。**改内容请同步改数值。**

## 2 头部三变体（v4 新增）

头部用 CSS Grid 承载，DOM 不变，只换 `grid-template-areas`：

| 变体 | 布局 | 高度 | 说明 |
|---|---|---|---|
| `two` | `"title x" / "lead lead"` | 74px | 标题一行 + 完整句说明一行。信息最全，但占 27% 弹框高 |
| `one` ← **推荐** | `"title lead x"` | **52px** | 标题与短说明同行。弹框降到 **256px**，动线更紧凑 |
| `tint` | 同 `one` + `bg-panel-alt` 底色 | 58px | 再给头部垫底色拉开层次（新建会话弹窗的头部就是这个处理） |

**推荐 `one`**：两行时说明文字「请选择这次关闭的行为。」只起"这里要选一下"的作用，
而卡片本身已经把这个意思表达完了；压成一行后弹框更精神，且层级仍清晰
（标题 15px/700 vs 说明 12px/text-2）。

配套的**文案要跟着变短**（否则单行会挤）：

| | 两行变体（`two`） | 单行变体（`one`/`tint`） |
|---|---|---|
| 中文 | 请选择这次关闭的行为。 | 选择关闭方式 |
| English | Choose what closing should do. | Choose how to close |

## 3 卡片语义（v3 起）

**会话数写在卡片副标签上**，不再单独占一段列表——「会丢失什么」直接写在那张
**会导致丢失的按钮**上，比放在别处更贴合"卡片即操作"的语义。

| | 有 N 个会话 | 0 个会话 |
|---|---|---|
| 最小化到托盘 | 保持 N 个连接 | 保持后台运行 |
| 完全退出 | **断开 N 个连接** | 关闭应用 |

| 项 | 规格 |
|---|---|
| 尺寸 | 高 82px，图标 22px，三行间距 7px |
| 默认态 | 边框 `border-subtle`，底 `bg-root` |
| 托盘卡 hover | 边框 `accent`，底 `chip`，图标 `accent` + 上移 1px |
| 退出卡 hover / **聚焦** | 边框 `close-red`，底 `close-red@14%`，图标 `close-red` + 上移 1px |
| 按下 | `scale(.985)` |
| 「默认」角标 | 30×15，圆角 3，`chip` 底 + `accent` 字 9px/700，`right:6 top:6`；仅当设置里该项为默认时渲染 |

**卡片即操作** —— 点哪张执行哪个，底部不放「关闭」主按钮；破坏性预警由退出卡的
hover / 聚焦变红承担。

## 4 交互契约（与 Rust 侧一致）

| 动作 | 结果 |
|---|---|
| 点 × / 点「取消」/ 按 Esc | 关闭卡片，不执行任何动作 |
| 点托盘卡 | `close-confirmed(勾选 ? "tray,remember" : "tray")` |
| 点退出卡 | `close-confirmed(勾选 ? "exit,remember" : "exit")` |
| 点遮罩 | **不关闭**（卡片即操作，误点遮罩不该关） |

`parse_close_mode()` 取前缀 `tray`/`exit`；`close_mode_remembers()` 看后缀 `remember`。

### 5.1 第二轮修正（用户复测截图）

**1. 头部整组跑到弹框正中**

`HorizontalLayout` 上的 `alignment: center` 是 **主轴（水平）** 对齐 —— 即便说明文本带了
`horizontal-stretch: 1`，整组「标题 + 说明 + ×」仍会被推到正中，标题与左侧脱开。
**去掉即可**，按声明顺序左排后说明吸收剩余空间、× 自然贴右。

**2. 「取消」按钮被撑到 200px+**

上一轮为修「取消」偏右，给**布局里**的 `glyph-t` 设了
`width: (collapse && glyph == "") ? 0px : self.preferred-width;`。

**在布局内显式设 `width` 会同时钉住 min/max-width 并覆盖布局分配** —— 结果不是缩小图标，
而是把整个按钮撑开。改为根治写法：另放一个 **0 尺寸、绝对定位的测量 Text**
（父是 Rectangle 而非布局）专门提供图标宽度给 `natural-w`；布局里的图标改回
**`if` 条件实例化**（空 glyph 时元素根本不存在）。`collapse-empty-glyph` 开关随之删除。

**3. 点「完全退出」要按两次（已回退 §5 表格第 6 条）**

现象：第一次点击**连卡片都不关**，但 hover 正常。

根因：上一轮为补键盘聚焦态，在「完全退出」卡上叠了一个 `exit-focus := FocusScope`。
**FocusScope 被点击时会自己去获取焦点、并把这一击消费掉** —— 第一次点击到不了下层的
`TouchArea`（`clicked` 不触发、卡片也不关）；第二次点击时它**已经有焦点**了，不再消费，
才落到按钮上。**已移除该 FocusScope**，危险预警回到只由 hover 承担。

> 键盘聚焦态留了 TODO：要恢复必须找一种**不消费点击**的写法（例如把 FocusScope 压到
> 0 尺寸再单独处理 Tab），不能直接盖在卡片上。

**4. 两张卡不等宽**

`horizontal-stretch: 1` **不保证等宽**：布局按「preferred + 均分剩余」分配，"最小化到
托盘"（6 字）比"完全退出"（4 字）preferred 宽约 24px，最终卡片就宽约 16px。

修法：两张卡都设 `min-width: (parent.width - 10px) / 2` —— 它恰好等于可用宽的一半，
min 已占满全部空间，布局没有剩余可以偏向，于是强制等宽。

**验证**：`cargo check` EXIT=0，warning 17 条（基线 19 条，无新增）；
app.slint 的 65 条 `@tr` 全部在 zh/en po 里有条目。
